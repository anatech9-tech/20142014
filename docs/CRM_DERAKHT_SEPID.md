- `crm_derakht_sepid/` — کل کد پروژه (از فایل `htdocs.txt` استخراج و بازآرایی شد)

- `crm_derakht_sepid/config.local.php` — **گیت‌نمی‌شود** — اطلاعات دیتابیس جدید همینجاست
- `docs/PROJECT_BLUEPRINT.md` — نقشهٔ راه کلی
- این فایل — منبع حقیقت وضعیت پروژه

## ۲) منبع پروژهٔ فعلی و ساختار آن (تحلیل‌شده)

فایل ارسالی `htdocs.txt` در واقع یک **ZIP** بود که باز شد و فایل‌هایش مستقیماً زیر `crm_derakht_sepid/` قرار گرفت (پوشهٔ `htdocs` و پوشهٔ آپلود قبلی کاملاً حذف شدند).

**آمار:** ۷۴ فایل PHP • ۹ JS • ۸ صفحهٔ HTML/استاتیک • ۵ تصویر/آیکن • ۳ CSS • PWA کامل (Service Worker + Manifiest) • حدود **۳۰٬۰۰۰ خط** کد.

**پشتهٔ فنی فعلی:** PHP خالص (Procedural + PDO با Prepared Statements) • MySQL/MariaDB utf8mb4 • جلالی کامل (ورود/خروجی تاریخ شمسی) • سه‌زبانهٔ fa/ar/en • Tailwind-style CSS دستی (glass.css) • AJAX JSON endpoints • Web Push (VAPID) • Excel export بدون کتابخانه.

**الگوی معماری:**
```
مرورگر ──► index.php (تک‌نقطهٔ ورود + گیت CSRF سراسری روی همهٔ POSTها)
              │
              ├─ pages/*.php   (۵۰+ صفحهٔ ماژول)
              ├─ api/*.php     (JSON API: work_orders, notifications, switch_workshop, download_excel)
              └─ push/*.php    (Cron ارسال Web Push)
                     │
config.php ──────────┤  session + CSRF + Jalali + helpers + PDO
includes/ ───────────┘  lang.php/legacy_i18n* (fa/ar/en) • salary_calc.php • arash_coin.php (stub بی‌اثر — ماژول WTTP COIN حذف شد) •
                        operations_hub.php (بکاپ DB خودکار، audit) • excel_*.php
```

**مدل دسترسی فعلی (RBAC+):** `admin` (مدیر کل) ▸ `project_manager` (پروژه‌ای) ▸ `workshop_manager`/`manager` (مدیر واحد) ▸ کاربر عادی + پرمیشن‌های ریز از جدول `user_permissions` + گیت صفحه‌ای `user_page_access` (full/viewer با انقضا) + نقش‌های مخصوص خواندنی: `nazer_kol`/`nazer` (ناظر کل — همه‌چیز read-only) و `karfarma` (کارفرما — فقط فرم‌ها/پرینت) + حساب‌های خاص `yaser`, `javidhse`.

**جدول‌های دیتابیس (۶۰+ جدول)** — مکان‌ها: users, user_permissions, user_page_access, workshops, workshop_personnel, workshop_settings, work_hours, missions, employee_breaks, temp_entry_grants, leave_requests, holidays, salary_history, salary_calculations, advances, advance_expenses, bonuses_penalties, petty_cash, daily_reports, work_orders, work_order_items, anbar_reports, inventory_items, inventory_transactions, inventory_serials, purchase_requests, pending_transfers, subcontractors(+services, face_items, daily_entries, entry_items, payments — فقط برای «ارسال برای تعمیر» انبار نگه داشته شد)، archive_folders/files, personnel_documents, notifications, notification_recipients, push_subscriptions, chat_channels, chat_channel_members, chat_messages, audit_log, settings, settings_requests.
> `hse_reports` و `arash_coin_*` دیگر در نصب تازه ساخته نمی‌شوند (روی هاست‌های قدیمی دست‌نخورده باقی‌اند — keep_db). `bonuses_penalties` عمداً نگه داشته شد چون محاسبهٔ حقوق (`salary_calc.php`) مستقیماً از آن می‌خواند.
> ستون‌ها از تمام `INSERT`/`UPDATE`/`SELECT` کد استخراج و در `install_db.php` بازسازی شد. فایل `migrate.php` اصلی **در فایل ارسالی وجود نداشت**؛ به همین دلیل schema نصب‌کننده بازنویسی شد.

## ۵) یکپارچه‌سازی VoIP — تلفنچی (اطلاعات تأییدشده از مستندات رسمی)

- پایهٔ API: `https://panel.telefonchy.com/webservice/v1/`
- احراز هویت: هدر **`webservice-token: {TOKEN}`** (از پنل: «my/auth») — فقط سمت سرور، هرگز در JS/گیت
- سرویس‌ها: `GET /webservice/v1/services` → لیست سرویس/خطوط/داخلی‌ها (برای جدول `voip_extensions`)
- **ایونت تماس (Webhook):** پنل تلفنچی → آدرس `https://YOUR-DOMAIN/api/voip_webhook.php` ارسال می‌کند؛ دو رویداد `ringing` و `hangup`؛ با بدنه JSON شامل `data.webservice_token` (باید با توکن ذخیره‌شده برابر باشد) + `src`/`dest`/`cuid`/`type: incoming|outgoing` — نکتهٔ مهم: اعداد به‌صورت **مخفی‌شده** می‌آیند؛ **شناسهٔ کامل تماس را از `cuid` با API «دریافت اطلاعات یک تماس»** تکمیل می‌کنیم
- **CDR:** دریافت جزئیات تماس‌ها (فیلتر تاریخ/داخلی/ورودی-خروجی) → جدول `voip_calls`
- **Click-to-Call:** `POST` ایجاد تماس از داخلی کارشناس به شمارهٔ مشتری — دکمهٔ تماس در پروفایل مشتری
- **ضبط مکالمه:** دانلود با `file_id` + `cuid` → ذخیرهٔ لینک در `voip_calls` (یا آرشیو)
- **تحلیل هوشمند تماس (AI تلفنچی):** ثبت درخواست تحلیل → پیگیری وضعیت → دریافت خلاصه + متن مکالمه + احساس مشتری + کلیدواژه‌ها → ذخیره در `voip_calls.ai_summary`
- **اقدام لازم:** آدرس وبهوک و داخلی‌های هر کارشناس باید روی پنل تلفنچی ست شود؛ توکن وب‌سرویس باید **توسط شما** در اختیارم گذاشته شود (یا در `config.local.php` قرار گیرد)

> نکته: من نمی‌توانم از همین‌جا به پنل تلفنچی شما وارد شوم؛ فقط کد یکپارچه‌سازی را می‌نویسم و شما توکن را ست می‌کنید.

## ۶) یکپارچه‌سازی AI

- سرویس `includes/ai_client.php` با همان الگوی «OpenAI-compatible» (base_url + api_key + model از `config.local.php`)
- قابلیت‌ها: خلاصهٔ مشتری/پرونده، پیشنهاد اقدام بعدی، نوشتن پیش‌نویس پیش‌فاکتور و پیام به مشتری، تحلیل متن چت/تماس، گزارش مدیریتی روزانه («امروز چند سرنخ آمد؟ چه کسی عقب مانده؟»)
- کنترل هزینه: ثبت مصرف در `ai_logs` + محدودیت نقش (مدیر کل/مدیر تیم) + صف اختیاری
- **نیازمند از شما:** سرویس‌دهنده (OpenAI/OpenRouter/…) و کلید API

1. `config.php` قبلاً **رمز دیتابیس اصلی کارگاهی** (ممیزِ قبلی کارگاهی) را در خود داشت؛ از کد حذف و جایگزین `CHANGE_ME` شد. **پیشنهاد قاطع:** آن پسورد قدیمی DB را تغییر دهید (چون داخل فایل ارسالی بود).
2. `push/vapid.json` شامل **کلید خصوصی VAPID واقعی** بود؛ حذف شد و جایش `vapid.example.json` با مقادیر نمونه ساخته شد. **کلیدهای VAPID جدید بسازید** (یک دستور: `web-push generate-vapid-keys` یا هر ابزار آنلاین) و روی هاست جدید جایگزین کنید.
3. اطلاعات دیتابیس **جدید** فقط در `config.local.php` است که گیت‌نمی‌شود — ولی چون در همین گفت‌وگو هم آمده، هرجا چت لو می‌رود را محرم بدانید؛ در صورت امکان پس از نصب، پسورد DB را عوض کنید.
4. `install_db.php` پس از اجرا **باید حذف شود** (در خود صفحه هم گفته می‌شود).
5. این ۳ فایل را هرگز در گیت/فوروارد قرار ندهید: `config.local.php`, `push/vapid.json`, `backups/*`.

فایل `docs/COMPANY_ORG_POLICY.md` — متن کامل ۲۶ اسلایدیِ «ساختار سازمانی، شرح وظایف و نظام حقوق و کمیسیون» (فایل اصلی pptx در مخزن نگه‌داری نمی‌شود؛ تصمیم کارفرما). نکات کلیدی که طراحی را می‌سازند:
- **دو جریان درآمدی:** (الف) تأمین سفارشی Sourcing-to-Delivery (استعلام چین → تأیید/پیش‌پرداخت → خرید → حمل/ترخیص → تحویل → تسویه)؛ (ب) واردات ثابت و فروش موجودی (Trading). «هیچ سفارش/فروشی بدون ثبت بهای تمام‌شده، قیمت فروش، وضعیت وصول و مسئول مشخص وارد گزارش کمیسیون نمی‌شود.»
- **ساختار مرحلهٔ اول:** مدیرعامل/بازرگانی (روابط خارجی+خرید چین+قیمت‌گذاری نهایی) ← مدیر فروش ← هماهنگ‌کنندهٔ سفارشات + مالی/اداری برون‌سپاری + **۴ کارشناس فروش (تلفنی/آنلاین/سازمانی)** + خدمات برون‌سپاری؛ نقش **توسعه بازار (Business Development)** جدا از فروش است (سایت/شبکه‌سازی/نمایشگاه) — «در شروع می‌تواند یک نفر باشد و با مدیر فروش تداخل نداشته باشد».
- **تارگت‌ها (شش‌ماههٔ استقرار):** واحد فروش ۵٬۰۰۰M تومان/ماه (هر کارشناس ۱٬۲۵۰M — ۲۵٪ِ تیم) + توسعه بازار ۵۰۰M؛ از ماه ۷ بازنگری ۱۵–۲۵٪ فصلی با بررسی در پایان ماه پنجم.
- **کمیسیون از سود ناخالص محقق‌شدهٔ وصول‌شده (نه مبلغ فاکتور):** کارشناس: <۷۰٪→۱۰٪ | ۷۰–۹۰٪→۱۵٪ | ۹۰–۱۰۰٪→۱۸٪ | ۱۰۰–۱۲۰٪→۲۲٪ | ≥۱۲۰٪→۲۵٪(سقف). مدیر فروش: <۷۰٪→۳٪ | ۷۰–۹۰٪→۵٪ | ۹۰–۱۰۰٪→۷٪ | ۱۰۰–۱۲۰٪→۸٪ | ≥۱۲۰٪→۱۰٪(سقف). توسعه بازار: پاداش از سود مشتریان جدید منتسب — تارگت ۵۰۰M: <۵۰٪→۱۰٪ | ۵۰–۱۰۰٪→۲۰٪ | ۱۰۰–۱۵۰٪→۲۵٪ | ۱۵۰–۲۰۰٪→۳۰٪ | ≥۲۰۰٪→۳۵٪(سقف).
- **تعریف سود ناخالص معامله:** فروش خالص وصول‌شده − بهای خرید − حمل/بیمه − حقوق و عوارض ترخیص − سایر هزینه‌های مستقیم تا انبار (بدون مالیات بر ارزش افزوده؛ هزینه‌های عمومی کسر نمی‌شود؛ تخفیف/برگشت/خسارت از سود کسر می‌شود). کمیسیون متناسب با وجه وصول‌شده؛ مانده وصول‌نشده از محاسبه خارج است.
- **قواعد انتساب (ضد اختلاف کمیسیون):** لید قبل از اولین تماس با تاریخ و منبع در CRM ثبت شود؛ پاداش توسعه بازار فقط برای مشتری جذب‌شدهٔ دارای منبع اثبات‌شده؛ مشتری تکراری تا ۱۲ ماه پس از جذب طبق سیاست تمدید؛ بدون دوباره‌شماری سهم جذب/فروش؛ مبنای قطعیت فقط پس از وصول.
- **حقوق ثابت پیشنهادی:** کارشناس ۲۳–۲۸M | مدیر فروش ۳۵–۴۵M | توسعه بازار ۳۰–۳۵M | هماهنگ‌کننده سفارشات ۲۸–۳۵M | حسابدار = برون‌سپاری.
- **چرخهٔ سفارش استاندارد** با «نقاط توقف اجباری» (بدون مشخصات فنی و تأیید قیمت خرید نشود؛ بدون تأیید وجه پرداخت چین نشود؛ بدون ثبت هزینه‌های واقعی کمیسیون قطعی نشود) و KPIهای هر نقش.
- **اثر بر طراحی (Phase 2/4/AI):** نقش‌ها/تیم‌ها باید با کانال‌های «تلفنی/آنلاین/سازمانی + توسعه بازار» هم‌راستا شوند؛ انتساب از لحظهٔ ثبت لید در CRM اجباری است (فیلد منبع و تاریخ)؛ موتور کمیسیون باید **پیکربندی‌پذیر** باشد (تارگت/درصد/سقف هیچ‌وقت هاردکد نشود)؛ AIِ مربی می‌تواند روی همین مراحل قیف و «سود به‌جای فاکتور» آموزش ببیند/امتیاز بدهد.
- ✅ این سند **«نهایی»** اعلام شده است (تأیید کارفرما ۲۰۲۶-۱۱-۱۰).
- **مدل‌سازی در برنامه (پیاده شد — ۲۰۲۶-۱۱-۱۰، کامیت `org-roles`):** «نقش سیستم» (`users.role`) دست‌نخورده می‌ماند و فقط سطح دسترسی است. جایگاه سازمانی لایه‌ای جداست: جدول مرجع `org_roles` (`code`/`name`/`stage`=stage1|growth/`sort_order`/`is_active`؛ بذر: ceo، sales_manager، sales_expert، order_coordinator، business_development، accountant_outsourced در مرحلهٔ استقرار + ops_manager، finance_manager در چارت رشد) + ستون `users.org_role_id`. تخصیص از صفحهٔ «تیم‌های فروش» (ادمین) با انتخاب «سمت سازمانی» (optgroup مرحلهٔ استقرار/توسعهٔ مرحله‌ای) انجام و با `operations_audit` ثبت می‌شود. کانال فروش و توسعهٔ بازار با **تیم** مدل شده‌اند (بذر نصب تازه: `sales_phone`/`sales_online`/`sales_b2b`/`bd` — توسعهٔ بازار عمداً تیمی جدا تا انتساب/کمیسیون دوباره‌شماری نشود). پیاده‌سازی self-heal است (همان الگوی صفحهٔ تلفنچی): جدول/ستون در اولین بار به‌طور idempotent ساخته می‌شوند؛ `install_db.php` هم برای نصب‌های تازه به‌روز شده. هیچ تارگت/درصدی از سند در کد هاردکد نشده (موتور کمیسیون پیکربندی‌پذیرِ فاز ۴ از تنظیمات خواهد خواند).

## ۱۲) چشم‌انداز بعدی — «CRM فروش تلفنی + هوش مصنوعی» (🟢 شروع شد — چراغ سبز ۲٠٢٦-۱۱-۰۹)

تصمیم کارفرما (۲۰۲۶-۱۱-۰۹): این کار هنوز شروع نمی‌شود؛ فقط برای نگهداری. وقتی چراغ سبز داد شروع می‌کنیم.

**آنچه در ذهن است (به بیان کارفرما):**
- CRM مخصوص **کارشناسان فروش تلفنی** متصل به **API تلفنچی**.
- اتصال به **GapGPT API** (گیت‌وی ایرانی به چندین مدل هوش مصنوعی) — کلید API را دارد.
- روی سایت یک **ایجنت هوشمند** می‌خواهیم که:
  1. **صوت مکالمهٔ تماس را از تلفنچی می‌گیرد**، تحلیل می‌کند، ایرادها را می‌گوید و **راهنمایی** می‌دهد؛
  2. **فرم مشتری جدید را خودکار پر می‌کند** (هر چی که از مکالمه فهمیده) و مشتری را به همان کارشناسِ پاسخ‌دهنده وصل می‌کند تا بعداً با زنگ زدن معلوم شود این مشتری مال کدام کارشناس است؛
  3. به **مدیر فروش** تحلیل می‌دهد و **کارشناسان را رتبه‌بندی** می‌کند؛
  4. در **پنل ادمین** مدیر با آن صحبت می‌کند و کارهایش را می‌سپارد؛
  5. توانایی **تعویض بین مدل‌ها** را دارد و برای هر کار، **بهترین/ارزان‌ترین مدل** را انتخاب می‌کند (کمترین هزینه، بهترین نتیجه).

**منابع خوانده‌شده (۲۰۲۶-۱۱-۰۹):**
- گپ جی‌پی‌تی — قیمت: DeepSeek V4.1 Flash ($0.15/$0.60/M) • GPT-6 Luna ($0.10/$0.50/M) • GPT-6 Sol ($2/$10/M) • Claude Sonnet 5.5 ($2/$10/M) • Claude Opus 5.5 ($4/$20/M) • Gemini 2.5 Flash TTS ($0.50/$10/M) • **GapGPT Whisper STT (~$0.006/دقیقه)** • Gemini Embedding ($0.15/M) • Jev 1.14 (پاسخ ساختاریافته/طبقه‌بندی ارزان) • Qwen Image 2.1 • GPT Image 2.5 — https://gapgpt.app/platform-v2/pricing?model=gapgpt-qwen-3.5
- تلفنچی — مرکز کمک: https://telefonchy.com/help — بخش «API و وب‌سرویس» شامل:
  - **دریافت صوت تماس** (`GET /webservice/v1/calls/record-quality/{rx|tx|merged}?cuid=…&record_id=…`، هدر `webservice-token`، پاسخ Binary/WAV) — راهنما: https://telefonchy.com/help/api/call-recording-download
  - **تحلیل هوشمند تماسِ خود تلفنچی** (ثبت `POST /calls/analysis/request` ← poll `GET /calls/analysis/show` ← `completed` → `summary`، `outcome`، `report_text`، `coaching_tip`، `coaching_reason`، `customer_sentiment`، `matched_keywords`، `transcript` + `transcript_by_role` (operator/customer)؛ نگاشت نقش فقط با `mapping=verified`؛ ۲۰۲ = در صف؛ هر POST یک واحد `remains` مصرف می‌کند) — https://telefonchy.com/help/api/call-ai-analysis
  - بخش «افزونه‌ها و یکپارچه‌سازی» فقط افزونهٔ وردپرسی دارد؛ آمادهٔ CRM ما نیست. Click-to-Call و ایونت تماس در API موجود است.

**تصمیم‌های معماری که هنوز گرفته نشده (بعداً با کارفرما):**
- تحلیل تماس با **خودِ تحلیل داخلیِ تلفنچی** انجام شود یا پایپ‌لاین خودمان روی **GapGPT** (یا ترکیبی: تلفنچی=رونویسی/خلاصه، گپ‌جی‌پی‌تی=استخراج فرم مشتری/نمره‌دهی/ایجنت چت)؟
- اتصال ایونت تماس (CDR webhook) نیازمند **آدرس HTTPS عمومی** است — قبل از لایو شدن VoIP باید هاست دامنه/SSL نهایی داشته باشد.
- ساختار «سه تا بخش جدا» (حرف قبلی کارفرما) و بودجه هر تماس.

**تصمیم‌های قطعی‌شده (۲۰۲۶-۱۱-۰۹):**
- چراغ سبز داده شد: مرحلهٔ بعد = **همین پروژۀ CRM فروش تلفنی + تحلیل خودمان**.
- ماژول/هوش مصنوعی آمادهٔ تلفنچی **خریداری نمی‌شود** — پایپ‌لاین خودمان را می‌سازیم (کنترل کامل روی فرم مشتری/نمره‌دهی/ایجنت).
- دامنه + HTTPS هاست **فعال است** (وب‌هوک CDR ممکن).
- **تصمیم معماری (۲۰۲۶-۱۱-۰۹): ترکیبی (Hybrid)** — کارفرما فعال‌سازی هوش مصنوعی خودِ تلفنچی را در نظر دارد (ارزان‌تر برایش می‌افتد). سهم تلفنچی AI: رونویسی (transcript_by_role) + خلاصه/نتیجهٔ تماس + احساس مشتری + کلیدواژه‌ها + coaching_tip. سهم گپ‌جی‌پی‌تی: استخراج ساختاریافتهٔ فرم مشتری از متن + نمره‌دهی/رتبه‌بندی کارشناسان + گزارش مدیریتی + ایجنت چت ادمین + هرکاری که تلفنچی نمی‌دهد (یا برگشت به‌عنوان fallback اگر تحلیل تلفنچی شکست خورد/mapping=unknown). اتصال مشتری→کارشناس از روی CDR (داخلیِ پاسخ‌دهنده) تعیین می‌شود، نه از متن. پیاده‌سازی پشت یک کلید `analysis_provider` (telefonchy|gapgpt) انجام می‌شود تا هرکدام بدون بازنویسی قابل جایگزینی باشد.
- پیشنهاد انتخاب مدل بر عهدهٔ بنده است (تنوع مدل روی حساب هست)؛ کارفرما سقف هزینهٔ ماهانه را بعداً تأیید می‌کند.

**چیزهایی که وقتی چراغ سبز داد لازم دارم (فعلاً نفرست؛ بعداً یک‌جا بده):**
1. `webservice-token` تلفنچی (+ اگر محدودیت IP دارد، IP هاست) • `service_id`
2. فهرست داخلی‌ها + اینکه هر داخلی مال کدام کارشناس است
3. آیا CDR/ایونت تماس (وب‌هوک) روی تلفنچی فعال است/باید فعال شود؟ — با پشتیبانی تلفنچی (02191300010)
4. کلید API GapGPT + اینکه دقیقاً کدام مدل‌ها روی حساب فعال‌اند و سقف هزینهٔ ماهانهٔ مطلوب چقدر است
